# Plan: Laporan Keuangan & Formula SHU — Point Flow

> Status: **disetujui** — semua poin keputusan sudah final (lihat section 1).
> Siap dijadikan acuan roadmap/implementasi.
> Terakhir diperbarui: 2026-11-09

## 1. Konteks

Point Flow saat ini hanya memiliki **laporan operasional**: daily/monthly sales, stock,
stock movements, purchase orders, goods receipts, stock adjustments, payroll, dan
dashboard. Dua fitur berikut **belum ada sama sekali**:

1. **Laporan Keuangan** — pencatatan & penyajian pendapatan, pengeluaran, arus kas,
   laba rugi, dan posisi keuangan.
2. **Formula SHU** — perhitungan Sisa Hasil Usaha berbasis kontribusi transaksi anggota.

### Keputusan yang sudah disepakati (hasil diskusi)

| Topik | Keputusan |
|---|---|
| Pendekatan akuntansi | **Sederhana & derivatif** — tanpa COA/jurnal double-entry. Laporan dihitung dari data operasional + satu modul pencatatan manual |
| Modul anggota | **Ditambahkan** — bisnis apa pun yang sekalian mengelola data anggota/member |
| Dasar SHU per anggota | **Kontribusi transaksi saja** (tanpa komponen setoran modal) |
| HPP | **Snapshot saat transaksi**: kolom `unit_cost` baru di `sale_items`, diisi dari `product_skus.purchase_price` saat sale dibuat. Sales lama (pra-migrasi) pakai harga berjalan sebagai fallback |
| Posisi keuangan | **Versi sederhana**: Kas + Persediaan (nilai beli) + Laba kumulatif |
| Naming teknis fitur SHU | **Full English** — modul/tabel/endpoint memakai `profit_sharing` / `/profit-sharing/periods`. Istilah "SHU" hanya tampil di UI via i18n (locale `id`); locale `en` menampilkan "Profit Sharing" |
| Bucket alokasi | **Kolom fixed untuk v1** — 6 bucket default (`member_pct`, `reserve_pct`, `management_pct`, `supervisor_pct`, `social_pct`, `education_pct`) dengan CHECK total 100%. Upgrade path ke tabel bucket configurable tanpa merombak snapshot |
| Member di storefront online | **Wajib login** agar belanjanya tercatat SHU; member didaftarkan **oleh admin** (tanpa registrasi mandiri online). Guest flow tetap ada, tidak teratribusi, dan **tidak bisa di-assign manual** setelah masuk |
| Auth member | **Terpisah dari auth staff** — identitas **telepon (unique) + password**, JWT member-scope terpisah dari dashboard. Password awal di-set admin saat pendaftaran, member bisa ganti sendiri, admin punya tombol reset. Tanpa email verification / OTP di v1 |
| `is_cash` di financial_transactions | **Pakai field** `is_cash` (default `true`) — transaksi tunai memengaruhi arus kas, non-tunai tidak |
| Retur penjualan vs kontribusi anggota | **Net** — retur mengurangi kontribusi transaksi anggota untuk SHU |
| Penomoran dokumen | `FIN-` / `MBR-` mengikuti pola `TRX-` / `CRS-` yang sudah ada |

CREATE TYPE financial_transaction_status AS ENUM ('completed', 'cancelled');

    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

    cancel_reason TEXT,
    recorded_by BIGINT NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),

**Formula laba rugi (income-statement):**

```text
Pendapatan penjualan = Σ sales.total_amount (completed) − Σ sale_returns.subtotal (completed)
HPP                  = Σ sale_items.quantity × COALESCE(sale_items.unit_cost,
                        product_skus.purchase_price)   [sales completed, dikurangi retur proporsional]
Laba kotor           = Pendapatan − HPP
Beban gaji           = Σ payroll_slips (base_salary + bonus − deduction) per periode
Beban lain           = Σ financial_transactions (expense, completed) per periode
Laba bersih          = Laba kotor − Beban gaji − Beban lain
```

**Formula arus kas (cash-flow):**

```text
Kas masuk  = Σ sales (completed) + Σ financial_transactions income (is_cash)
Kas keluar = Σ cash_drawer_movements (cash_out, cash_drop, petty_cash)
           + Σ financial_transactions expense (is_cash)
Net arus kas = masuk − keluar (per periode)
```

**Formula posisi keuangan (financial-position, as-of date):**

```text
Kas            = kumulatif arus kas dari transaksi pertama s/d as_of
Persediaan     = Σ stok tersisa × purchase_price (dari v_stock_report)
Laba kumulatif = laba bersih dari transaksi pertama s/d as_of
Output         = { kas, inventory_value, total_assets, cumulative_net_profit }
```

## 3. Tahap 2 — Modul Anggota + Member Auth

> Member bisa belanja online lewat dua jalur: **login sebagai member** (belanjanya
> tercatat untuk SHU) atau **guest** seperti alur sekarang (tidak teratribusi).
> Member hanya bisa didaftarkan oleh **admin** dari dashboard — tidak ada registrasi
> mandiri di storefront. Guest order **tidak bisa** di-assign member manual setelah
> masuk.

### 3.1 Migration `012_add_members.sql`

```sql
CREATE SEQUENCE members_member_no_seq START WITH 1 INCREMENT BY 1;

CREATE TABLE members (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    member_no VARCHAR(40) NOT NULL DEFAULT (
        'MBR-' || to_char(now(), 'YYYYMMDD') || '-' ||
        lpad(nextval('members_member_no_seq')::TEXT, 6, '0')
    ),
    full_name VARCHAR(160) NOT NULL,
    phone VARCHAR(30) NOT NULL,              -- identitas login member (unique)
    email VARCHAR(160),                      -- opsional
    password_hash TEXT NOT NULL,             -- di-set admin saat pendaftaran (Argon2)
    address TEXT,
    joined_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    is_active BOOLEAN NOT NULL DEFAULT true, -- false = tidak bisa login & tidak masuk distribusi
    notes TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX members_phone_unique_idx ON members (phone);
CREATE INDEX members_name_idx ON members (full_name);

CREATE TABLE member_refresh_tokens (         -- terpisah dari refresh_tokens staff
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    member_id BIGINT NOT NULL REFERENCES members(id) ON DELETE CASCADE,
    token_hash TEXT NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    revoked_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX member_refresh_tokens_member_idx ON member_refresh_tokens (member_id);

ALTER TABLE sales ADD COLUMN member_id BIGINT REFERENCES members(id) ON DELETE SET NULL;
ALTER TABLE sales ... CREATE INDEX sales_member_idx ON sales (member_id);
ALTER TABLE online_orders ADD COLUMN member_id BIGINT REFERENCES members(id) ON DELETE SET NULL;
ALTER TABLE online_orders ... CREATE INDEX online_orders_member_idx ON online_orders (member_id);
```

### 3.2 Backend

Modul baru `backend/src/modules/members/` — CRUD oleh staff (dashboard):

```text

POST   /members
GET    /members/{id}
PUT    /members/{id}
DELETE /members/{id}   (soft-delete via is_active, atau hard-delete bila belum dipakai)
```

Endpoint auth member (public, mengikuti sub-router `/public/*` terenkripsi di
modul online_orders):

```text

POST /members/auth/refresh
POST /members/auth/logout
GET  /members/auth/me
POST /members/auth/change-password
```

Aturan auth & atribusi:

- JWT member **member-scope**: hanya berlaku untuk endpoint auth member + checkout
  storefront. Extractor staff menolak token member; extractor member menolak token
  staff — dua dunia tidak boleh saling menembus.
- Password: admin mengisi saat pendaftaran, member bisa ganti sendiri setelah login,
  admin punya tombol reset per member.
- Checkout online: Bearer token member → `member_id` **diambil dari token** —
  request body tidak pernah menerima `member_id` (anti-spoof). Identitas pembeli
  diambil dari profil member; alamat delivery default dari profil, tetap bisa diedit
  per order.
- Tanpa token → guest: `member_id` NULL, identitas diketik bebas seperti alur sekarang.
- Konversi order → sale (saat pembayaran online dikonfirmasi) **menyalin `member_id`**
  ke sales — kalau tidak, belanja online member tidak pernah masuk kalkulasi SHU.
- Kontribusi SHU hanya dari transaksi dengan `member_id`; tidak ada mekanisme
  pemberian SHU ke order guest.

### 3.3 Frontend

- Dashboard: halaman `master/members` (CRUD, pola page CRUD yang ada) — form member:
  telepon wajib & unique, password awal di-set admin; aksi **reset password** per member.
- Picker anggota opsional di alur kasir (POS): dialog pencarian via member_no/telepon

- Storefront: login/logout, halaman profil + ganti password; checkout terdeteksi login

- API layer: `lib/api/members.ts` (dashboard); auth & profil member di

## 4. Tahap 3 — Modul Profit Sharing (fitur SHU)

> Naming teknis 100% English (`profit_sharing`), konsisten dengan konvensi repo.
> Istilah "SHU / Sisa Hasil Usaha" dipakai hanya di layer UI via i18n — locale `id`
> menampilkan "SHU", locale `en` menampilkan "Profit Sharing". Lihat tabel keputusan
> di section 1.

### 4.1 Migration `013_add_profit_sharing.sql`

```sql
CREATE TYPE profit_sharing_period_status AS ENUM ('draft', 'calculated', 'finalized', 'cancelled');

CREATE TABLE profit_sharing_periods (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    period_name VARCHAR(60) NOT NULL,          -- mis. 'Tahun Buku 2026'
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status profit_sharing_period_status NOT NULL DEFAULT 'draft',
    total_pool NUMERIC(14, 2),                 -- pool final; NULL = pakai auto (laba bersih)
    auto_net_profit NUMERIC(14, 2),            -- laba bersih periode saat calculate (audit)
    -- bucket alokasi kolom fixed v1 (persen, total = 100; nama bucket default):
    member_pct NUMERIC(5, 2) NOT NULL,         -- bagian anggota (dibagikan proporsional)
    reserve_pct NUMERIC(5, 2) NOT NULL,        -- dana cadangan
    management_pct NUMERIC(5, 2) NOT NULL,     -- manajemen/pengelola
    supervisor_pct NUMERIC(5, 2) NOT NULL,     -- pengawas
    social_pct NUMERIC(5, 2) NOT NULL,         -- program sosial
    education_pct NUMERIC(5, 2) NOT NULL,      -- program pendidikan/pelatihan
    CONSTRAINT profit_sharing_periods_pct_sum CHECK (
        member_pct + reserve_pct + management_pct + supervisor_pct
        + social_pct + education_pct = 100
    ),
    notes TEXT,
    calculated_at TIMESTAMPTZ,
    finalized_at TIMESTAMPTZ,
    finalized_by BIGINT REFERENCES users(id) ON DELETE SET NULL,
    cancelled_at TIMESTAMPTZ,
    cancelled_by BIGINT REFERENCES users(id) ON DELETE SET NULL,
    cancel_reason TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE profit_sharing_distributions (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    profit_sharing_period_id BIGINT NOT NULL REFERENCES profit_sharing_periods(id) ON DELETE CASCADE,
    member_id BIGINT NOT NULL REFERENCES members(id) ON DELETE RESTRICT,
    transaction_amount NUMERIC(14, 2) NOT NULL,  -- Σ net transaksi member selama periode
    share_pct NUMERIC(7, 4) NOT NULL,            -- kontribusi relatif thd total anggota
    share_amount NUMERIC(14, 2) NOT NULL,        -- jumlah yang diterima anggota
    calculated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT profit_sharing_distributions_period_member_unique
        UNIQUE (profit_sharing_period_id, member_id)
);
```

### 4.2 Aturan kalkulasi (transparan & terukur)

1. **Calculate** (hanya saat status `draft`/`calculated`, overwrite snapshot):
   - Hitung laba bersih periode via income-statement → simpan `auto_net_profit`.
   - `pool` = `total_pool` jika diisi, else `auto_net_profit`.
   - `member_pool` = pool × `member_pct` / 100.
   - Per anggota: `transaction_amount` = Σ net transaksi ber-member selama periode
     (penjualan − retur).
   - `share_pct` = transaction_amount ÷ Σ semua transaction_amount.
   - `share_amount` = member_pool × share_pct → snapshot ke `profit_sharing_distributions`.
   - Hanya member dengan `is_active = true` yang masuk distribusi.
   - Bucket non-anggota (cadangan, manajemen, dst.) hanya dilaporkan sebagai total per
     bucket di detail periode — bukan per orang.
2. **Finalize**: kunci snapshot secara immutable (perubahan data historis tidak
   mengubah hasil yang sudah final). Status → `finalized`.
3. **Cancel**: hanya sebelum finalize, wajib `cancel_reason`.
4. **Edit konfigurasi periode**: hanya saat `draft`.

2. **Anggota + member auth** — prasyarat atribusi transaksi profit sharing, baik dari
